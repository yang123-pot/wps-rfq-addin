用户确认逐字输入已不卡，但项目名称切换到单位名称仍严重卡顿。此前仅把整项目刷新从input移到change，未解决失焦时的重计算。

## 复现

同前包无头Edge产品页面，只读恢复实际960行项目；禁止项目save，WPS读表边界替代，其余产品计算真实执行。输入6字后触发change并聚焦单位名称。

- 修改前：切换2104ms，清单preview200次，项目assess8次；预览累计1447ms、评估141ms。
- 合成链路回归修改前因切框重合并205次而明确失败；消除重合并后，第二断言仍因阶段评估8次而失败。

## 修正边界

1. 导入集合的add/update/remove和项目restore均返回新collection。按collection对象及两个合并选择复用预览、合并确认键和自动分类键。抬头不参与这些键；来源修正、增删或合并选项改变会失效重算。没有缓存文件SHA核验，也没有缓存询价/拆分键。
2. 一次抬头同步刷新内，共享一份deliveryContext；回调结束finally释放，异步操作与下次刷新都重新取值。阶段评估从8次降到2次，询价模型按最新抬头构建。
3. 原有input轻量失效、四项校验、中文输入法、生成保存与严格内容键校验保持。没有改布局、业务文件、注册或运行服务。
