# 批准效果图变更说明（2026-10-11，用户要求）

本文件记录对已批准效果图的**用户要求的变更**。原 PNG 不重绘；变更以本说明＋用户提供的真实截图为准，验收时两者一起对照。

## 图03「表内审核」：最终分类允许输入新类别

**变更内容（用户 2026-10-11 要求）：** 图03 的「最终分类」列在保留下拉的同时，**允许用户直接输入下拉里没有的类别名**；该输入在整表一次确认时**按新类别接收**，并**同时写入类别库与经验（记忆）库**，作为下次自动分类的依据。同名重复输入按名称去重、不重复建类；新类别**直接生效**，不设“待审核”中间态。

**用户依据：** 用户在实时 WPS 中的截图（红框＝「最终分类」列 H，绿框＝「审核备注」列 I）——「最终分类」是用户自填区，「审核备注」用于写说明，两者互不影响。

**相对原图的接口变化：**

| 位置 | 原批准行为 | 现行为 |
| --- | --- | --- |
| 最终分类下拉 | 区域下拉，只允许库内类别（`Validation.Add(3,…)`） | 仍为区域下拉，但关闭校验错误提示＝**允许输入下拉以外的值**（`ShowError=false`） |
| 整表确认 | 库外类别名报 `category-unknown` 并阻断 | 库外类别名**按新类别接收**（空分类仍阻断） |
| 类别库 | 用户需在“分类库”面板手工新增类别 | 确认时**自动建类并保存**（同名复用原编号） |
| 经验库 | 只学习库内类别 | 新类别**一并学习**，下次自动建议可用 |

**落地与验证：** `workbook-layout.js`（`listValidation` 增 `allowOtherInput`）、`classification-review-model.js`（`validateRead` 增 `allowNewCategories`/`newCategoryIds`，新增 `adoptNewCategories`）、`export-host.js`（写入 `ShowError=false` 与读回检查）、`classification-ui.js`（`adoptCategories` 建类并落盘）、`import-ui.js`（确认路径先建类再解析）。模块测试：`workbook-layout`／`classification-review-model`／`export-host`；浏览器检查：`ui-sheet-review-check`（覆盖建类、入库、学习与同名去重）。

**边界：** 只改「最终分类」这一列的下拉行为；其他下拉（如汇总表“询价生成方式”）仍只允许库内值。真实 WPS 窗口内的手输行为待四项目验收时按项目实测并在证据中记录点击者。
