# 来源与异常核对验证

日期：2026-09-23。本记录描述来源核对任务完成时的验证。后续多文件导入、字节指纹及两种读取方式分别保存见[多文件导入验证](wps-multi-import-verification.md)；合并另存、分类及询价输出仍未实现。

## 实现行为

- 候选项展开“核对 / 修正此行”，逐行填写编码、名称、单位、工程量、工程及专业。按材料名推断或来源不明的记录必须明确核对；空名称/单位/来源和异常数量不能确认通过。
- 数值编码首次不自动预填，要求按原表显示手动输入，并勾选格式和前导零确认。原已有编码不能通过“无编码”选项清除；确实缺码的原行可以显式确认。
- “全部待核对问题”可将仅名称行确认为区段标题，或补齐字段作为材料，后者会重新计算后续来源。未识别行可补成材料，或填写理由确认为非材料说明。表头问题须回原表修复，不能直接消除。
- 特征续行逐行确认归属，可转到同表其他材料；保留原续行行号与初始归属。撤销导致续行不再成立时同步撤销依赖的归属记录，使原行重新进入待核对。
- 不写原始工作簿，全部修正叠加到读取快照副本。原编码、原数量、原来源保留在内部追溯记录，合并模块继续携带这些原值；修正后工程量仍为精确十进制字符串。
- 记录保存在当前侧栏的本机 localStorage，不上传GitHub。保存/恢复前重新读取当前工作簿；路径、名称、表范围或单元格值变化时拒绝旧记录。恢复需要显式点击，损坏/不兼容记录不部分恢复。
- 关闭前显示未保存状态，重新读取/恢复覆盖未保存修改前弹出确认；存储容量不足明确提示失败且保留页面内核对结果。核对记录列表支持分页及撤销。

## 已执行验证

- **68项Node测试通过**，其中10项核对核心测试覆盖修正原值保留、异常阻断、推断确认、区段重解析、续行转移/撤销、非材料理由、保存恢复、版本/损坏/不同文件保护、存储失败及数值编码确认。
- 两组Edge浏览器交互检查通过：既有读取/分页/定位保护；修正、保存、重载后恢复、撤销、原表变化拦截；区段转材料、续行重新归属、非材料确认、数值编码人工输入及保存失败反馈。380px宽度无水平溢出，截图已查看。
- 独立只读代码审查发现3项边界缺陷，分别补出失败回归测试后修复：数值编码隐式转文本绕过格式核对；区段提升后非材料决定与新续行冲突；撤销提升材料留下已转移的依赖续行。另在最终检查补测并修复区段提升后各表条数未刷新的显示问题。修复后全部测试和两组浏览器检查重新通过。
- 四项目共33张表、7,587条候选的已有真实数据快照回归通过。无核对时各材料名称、编码、特征、单位、数量和来源与解析结果逐字段一致；项目四106行续行无遗漏。每个样本均验证单条合成修正及序列化恢复，不把合成决定写回原件。四原件SHA256前后不变。
- 四项目空核对记录序列化大小约58/269/672/745KB，初次核对解析约15/60/112/143ms（本机Node测量，仅供参考）。容量不足路径另有模拟验证。

## 限制与后续验收

- 本轮浏览器使用合成WPS宿主；真实WPS中的定位、核对、关闭提示及重启后存储恢复仍待实机验收，不以浏览器测试替代。
- 保存一致性基于现有读取接口的路径、范围和单元格值，不是原文件字节指纹，也不检测仅显示格式的变化。数值编码由用户按原表显示确认；若之后仅改显示格式，需撤销对应编码核对重做。自动读取编码显示格式及文件指纹在导入/另存阶段继续处理。
- localStorage绑定本机侧栏来源地址，换机器、换开发服务端口或清理存储不会迁移记录；尚无核对记录导出/迁移工具。大项目存储超限时本次修改只能暂留页面，不能声称已保存。
- 表头不完整/重复等问题需修复原清单后重新读取，旧快照核对不迁移；本轮不做分类学习及批量来源确认。

复现：`node --test wps-addin/test/*.test.cjs`；开发环境提供Playwright与Edge后运行 `node wps-addin/test/ui-check.cjs`、`node wps-addin/test/ui-review-check.cjs`。本机运行证据保存在忽略目录 `outputs/source-review-*`，不上传原件、快照或运行记录。
