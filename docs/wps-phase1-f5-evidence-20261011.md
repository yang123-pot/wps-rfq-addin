## 6. 项目1 编码前导零结论

| 项 | 结果 |
| --- | --- |
| 输入件编码单元格 | 262 格，**全部为文本**、全部 12 位、**全部带前导零**（工作表分布 138 / 124） |
| 人工分类簿编码单元格 | 200 格，**全部为数值**、0 格文本、**0 格带前导零** |
| 不同编码（输入 / 人工） | 236 / 189 |

结论：项目1 的编码在**输入件**中始终以前导零文本保存、未丢失；**人工分类簿把编码存成了数值**，因此按原样逐位比对天然 0 命中（这正是 `R12-L` “编码+四字段完全匹配输入行 0”的原因）。这是显示格式/存储类型差异，不是编码缺失：规范化（去前导零）后 189 条人工编码全部对应输入件。**后续项目1 导入必须保留 12 位文本编码，人工侧旧编码不得直接当作对账键。**
