# 未合并清单：来源原表内分类审核（2026-10-19）

用户明确：不勾选“合并清单”时，插件不能把所有工作簿先拼成一份扁平审核成果；每本来源工作簿仍保留原工作表样式、标签和行顺序，只在原表右侧追加分类列，并继续执行整表审核。用户选择“在原表右侧追加分类列”。对应补充图 `13-source-table-review-amendment.svg` 已实际渲染查看。

## 已实现行为

- 整理方式为“分别保留清单”时，自动分类完成后按来源工作簿生成独立审核副本：`<原文件名>_分类审核.xlsx`。同一批次内全部副本放在新建的 `<项目>_分类审核_<时间>_<短ID>` 目录。
- 服务端先从本次导入的工作副本逐字节复制基础文件，再交由 WPS 追加审核列。`.xlsx` 来源保留原 OOXML 字节基础；`.xls` 来源保留兼容转换路径。原件和导入工作副本均不保存、不改写。
- 每张含材料的工作表只在已有有效列右侧追加：

  | 列 | 内容 |
  | --- | --- |
  | 建议分类 | 自动建议；无建议或冲突显示“待核对” |
  | 最终分类 | 唯一建议预填，其余留空；浅黄可编辑 |
  | 审核备注 | 用户选填 |
  | 行标识 | 隐藏列，保存稳定 rowId，不作为公开业务字段 |

- 原有工作表名称、标签顺序、小标题、合并区、列宽、行高、字体和原材料内容保持；不插入汇总页，不重排材料，也不把所有来源拼成一张表。
- 点击“打开核对表”会打开全部审核副本并停在第一份材料的最终分类格。问题弹窗、定位和提示同时带文件名、工作表和原表行号。
- 读取时按每个工作簿、每张原表和稳定行标识汇总全部材料；空分类、未知分类、固定材料内容被改动、删行、重复标识仍阻断确认。最终分类错误定位到该工作表实际追加列。
- 整表确认后仍使用同一项目快照、分类工作簿、品牌汇总、询价和拆分链路。项目恢复会逐份核对全部审核副本的路径与 SHA；整目录搬移会重写全部副本路径。
- 勾选“合并清单”时仍沿用单份 `<项目名>_分类审核成果.xlsx`，原有合并、聚类、10 列审核表和后续流程不变。
