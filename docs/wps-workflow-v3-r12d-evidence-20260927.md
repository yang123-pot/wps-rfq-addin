| `Hyperlinks.Add` 之后 | 16711680（纯蓝） | 5 | 2 | `分类工作簿\水泵.xlsx` |

**结论：故障是写入次序，不是属性回读或主题色。** 宿主在落地原生链接时会把锚点按自带“链接”样式改写成纯蓝＋下划线；先写字体必然被覆盖。把字体移到 `Hyperlinks.Add` 之后落地，重开读回与获批色逐位相同，因此**不扩大容差**：本包删除了入场改动里的“蓝色系”放行，恢复精确比对，宿主若在重开时改回自带链接色会明确报错而不是产出“看起来像”的文件。

同一小样还测了下拉来源回读（真实宿主）：

| 写入 | 回读 Formula1 | Type |
| --- | --- | --- |
| `='分类汇总表'!$M$1:$M$2` | `=分类汇总表!$M$1:$M$2`（丢引号，等价） | 3 |
| `='分类汇总表'!$M$1`（错区域） | `=分类汇总表!$M$1` | 3 |
| `=$M$1:$M$2`（无表名） | `=$M$1:$M$2` | 3 |
| 不带等号写 `'分类汇总表'!$M$1:$M$2` | `分类汇总表'!$M$1:$M$2` | 3 |

**结论：WPS 能可靠回读 Formula1，只是会归一化引号/等号写法。** 因此 `Type=3` 只能证明“这里是下拉”，不能证明来源正确；本包删除了 `Type===3` 的兜底放行，改为必须读回等价区域，同时保留对等价写法的兼容。
