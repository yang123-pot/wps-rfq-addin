# 清单识别与来源预览验证

日期：2026-09-22。此阶段实现只读识别和预览，尚未开放来源修正保存、合并、分类或询价输出。

## 行为

- 读取全部工作表，按表头定位编码、名称、特征、单位及工程量；保留名称、特征和单位中的空格、换行，以及文本编码的前导零。
- 识别候选条目、表头、区段、汇总、空行和特征续行，每行都有审计记录。缺少字段、数字编码的显示格式及不认识的表格明确提示，异常数量保留原值，不当作零。
- 专业优先来自区段/工程/工作表标题。用户本轮追加确认：无明确专业标题时按“项目名称”识别，显示“专业按项目名称识别”并待核对；配管、阀门、支架等通用名称不强行分专业。材料特征中的关键词不参与此兜底。
- 相邻且只有特征列非空的续行附到上一条候选中，保存各段原文和行号，并标记核对归属；隔着标题、空行或其他行的内容不自动连接。原价不进入材料数据对象。
- WPS侧栏提供每页候选数、全部待核对问题、20项分页预览、问题筛选、特征展开及原行定位。切换工作簿后拒绝错误定位；读取失败隐藏旧结果。修改原清单后需要重新读取。

## 验证结果

- 43项Node测试及Edge真实DOM检查已通过。浏览器检查使用合成WPS宿主，覆盖无宿主提示、读取/解析、分页、筛选、问题列表、定位、工作簿切换保护和失败后清空结果；这不是新增的WPS实机验证。
- 独立复核发现2项重要问题，已先复现失败再修复：无序号/换序清单的分页工程标题现在正确切换来源；只有名称的歧义行现在生成可定位问题，不再静默视为区段。新增回归测试及完整测试集通过，未再次请求重复复核。


第二条需要开发环境提供Playwright和Edge；不加入插件运行依赖。本机可将`NODE_PATH`指向Codex运行时的`dependencies/node/node_modules`。可选环境变量`RFQ_UI_SCREENSHOT`指定合成样例截图位置。

本地证据均在忽略的`outputs/wps-parser/`：`verification.json`记录样本数与哈希结果，`field-preservation.json`记录逐行字段核对，`*.parsed.json`记录来源及行审计，`ui-preview.png`是合成样例的浏览器截图。清单、快照及截图不随此提交上传。
