# 分类工作簿读回路径误报修复（2026-10-19）

## 真机现象

- 生成流程报“WPS未返回指定分类工作簿”。
- 新批次文件实际存在，只读检查为40页：分类汇总表、38个询价类别页、最后“无需询价”。
- 说明分类工作簿写入和“无需询价”末页均成功，失败发生在发布后的WPS重新打开核对。

## 根因

读回代码只接受WPS返回的`FullName`与请求路径逐字相等。WPS使用编码路径、规范化短路径，或返回同名但不同目录的工作簿对象时，正确文件会被误判。项目又在读回前提前保存了完成状态，造成“文件正确但回执待核对”的不一致。

## 修复

- 路径统一还原`file://`、`%xx`编码与`/`、`\`差异；先做规范化精确匹配。
- WPS返回对象名称与目标同名时，允许继续逐页核对，由页名、页序和行数决定成功，不按名称单独放行。
- 项目先保存为“待核对”，逐页核对通过后才标记完成；失败则保留待核对状态。
- 已完成但缺少读回的项目，补做现有文件只读页核，通过后恢复，不重复写文件。
- 服务端新增直接读取xlsx页名与行数的能力；WPS同名窗口冲突时仍可核对真实文件。
- 待核对状态的主按钮改为“核对现有分类工作簿”，并明确分类汇总表就是该工作簿第1页，避免被理解为重复生成。

## 验证

- 编码路径、规范化短路径、错误同名对象均有回归。
- 缺读回恢复用例断言不重写工作簿、同批次恢复、补回`readBack`。
- 全量Node **552/552**；常规浏览器UI **22/22**。
- 真实WPS新文件已确认为40页且末页正确；重新打开助手后应直接恢复核对状态。
