# 来源与异常核对实施计划

> 使用 superpowers:executing-plans 在当前已授权的 `feat/wps-phase1` 开发分支继续；按项目续作规则完成后验证、提交并推送。

**Goal:** 在现有侧栏修正来源和材料字段、确认区段与续行归属，并在本机保存及恢复。

**Architecture:** `review.js` 保存对原始快照的显式核对记录，重放到副本后重新解析；原始快照不变。核对后的解析结果沿用 `merge.js`，保存使用侧栏 localStorage，路径与完整快照一致才允许恢复。

**Tech Stack:** 原生 JavaScript、Node test、现有 Playwright 浏览器验证脚本。

**Spec:** `handoff.md` 下一步第1项及 `docs/wps-addin-phase1-design-v2.md`。

## Global Constraints

- 不写原表，不自动确认、不以缺失或异常数量当零。材料名称、特征、单位不自动修剪或换算。
- 来源修正逐行确认；原编码、原数量及续行原位置保留。代码/数量等有效性重新校验。
- 仅名称行可确认区段或补为材料；已识别特征续行可明确归属到同表材料。未知非材料行须填写理由，表头错误须回原表修复。
- 每条操作可撤销；未解决的问题继续阻断，不等同于完成分类。
- 保存明确反馈失败，不上传运行记录；未保存工作簿须先在WPS保存。内容变更时拒绝套用旧记录。

## Review Focus

- 数值编码必须人工输入包含前导零的文本；确认缺码不能消除数值格式问题。
- 区段改为材料后必须重新计算下游来源；材料修正不能清除无关问题。
- 续行重新归属后不重复、不丢失，目标限定同表真实材料；撤销目标时不留下悬空归属。
- 损坏、旧版本、其他路径或内容变化的记录不能部分恢复；保存失败不能显示成功。
- 切换工作簿、读取失败和未保存修改不能误写或悄悄丢失。
