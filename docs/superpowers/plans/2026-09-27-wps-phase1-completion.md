## 优先检查的五类失效

| 风险 | 应有行为 | 所属任务与验证 |
| --- | --- | --- |
| 已存在pending拆分件连续被检查 | 未逐值验证前始终待核对；SHA稳定不能冒充内容正确 | R12-E：连续三次reconcile/prepare与一次服务重启测试 |
| 项目草稿/确认已存，xlsx仍是旧值 | 明确两者差异并保留双方；恢复不能清空人工决定或误报ready | R12-C：H11磁盘空/快照有值；关闭重开和409失败 |
| 有效stage超过10分钟或成功后discard | 活跃stage保留；已发布回执仍可verify，清理不破坏成功 | R12-B：11分钟mtime/1小时票据、busy、重复清理 |
| 下拉类型正确但源错误；同名链接指错目录 | 拒绝错误源/错误完整目标；兼容真正等价的WPS表示 | R12-D：Type=3错误区域、另一根目录同名文件负例 |
| 允许公开的联系方式与意外泄漏混在一起 | 指定抬头值允许，额外联系方式/路径/列/原价拒绝 | R12-F：完整矩阵白名单、长编码和未知额外单元格 |

## 统一证据格式与提交检查

每包在 `docs/wps-workflow-v3-acceptance.md` 或其链接的独立证据文件记录：基线/最终提交、工作区是否含未提交改动、日期/操作者/WPS版本、对应图、操作、预期、实际、截图/文件审计路径、未完成项、下一包。本机使用 `outputs/wps-acceptance-<执行日期>/<包名>/` 新目录，不覆盖旧记录。

每份实际文件最少记：用途/profile、最终路径、SHA256、工作表名/可见性、行列数、公式数、公开值对账、空单价金额、版式/链接/下拉（适用时）、项目revision/inputKey及截图。摘要脱敏入Git，原始数据本机保存。

提交前执行 `git status --short`、明确文件 `git add -- <本包文件…>`、`git diff --cached --check` 与完整暂存diff审查；提交后普通 `git push origin feat/wps-phase1`，比较 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/feat/wps-phase1`。不要 `git add .` / `git add -A`，不要强推。失败保留本地提交并写“待同步”。
