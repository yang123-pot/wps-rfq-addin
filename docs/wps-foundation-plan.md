# WPS接入与清单读取实施计划

> 执行方式：superpowers:executing-plans，本任务内直接实现、验证、审查；用户已经正式授权推进，无须再次确认启动。

**目标：** 在本机WPS加载“项目询价”功能区和侧栏，读取当前工作簿所有清单页，并在独立测试文件上证明读写与另存可用。

**架构：** `wps-addin/`保存全新插件。使用原生JavaScript、HTML、CSS和WPS Application API，业务模块与宿主适配分开，Node原生测试运行器验证纯逻辑。本地开发服务只提供插件资源和明确启用的诊断端点；不上传清单，不接入旧网页后端。生产发布前另做离线打包任务。

**依据：** `docs/wps-addin-phase1-design-v2.md`；官方加载项开发说明与wpsjs 2.2.3的电子表格模板及publish开发注册方式。

## 约束与检查重点

- 首先只读原清单；写入/另存验证只能创建独立测试工作簿。不能关闭用户其他工作簿、覆盖原件、修改WPS安装目录的oem.ini。
- 使用独立开发分支在当前目录执行，便于访问不上传的真实样本及保持handoff入口一致；没有并发修改任务，暂不创建额外工作区。
- 现阶段接入测试与业务测试分开报告；COM读写成功不等于JS加载项已加载，网页预览不等于WPS运行成功。
- 超大UsedRange、偏移表头、单个单元格、空表、读取失败都要明确处理；任何工作表失败不能显示成完整导入。
- 新文件保存前检查路径已存在；失败保留当前原清单状态；开发服务只绑定127.0.0.1，不能暴露项目根目录。

## 任务1：宿主适配与接入自检

文件：`wps-addin/src/host.js`、`wps-addin/test/host.test.cjs`、`wps-addin/package.json`。

接口：`WpsHost.inspectWorkbook(application)`返回工作簿名、路径、工作表名字/UsedRange尺寸；`WpsHost.readWorkbook(application)`返回含每页起始行列、二维单元格值的快照。另存探针归入任务2的开发验证文件，避免向产品宿主模块加入只供测试使用的方法。

- [x] 写行为测试：无活动工作簿应报错；多页偏移范围按原坐标返回；单值规范成二维数组；范围超限在取值前拒绝；读取失败指出页名；数据矩阵截断不能视为读取成功。
- [x] 运行`node --test wps-addin/test/host.test.cjs`，确认缺失实现导致预期失败。
- [x] 实现宿主适配，限定每表最大100万、整本300万单元格；多单元格Value2必须返回正确矩阵，缺失接口不伪造成功。
- [x] 重跑完整`node --test wps-addin/test/*.test.cjs`；10项通过，核对没有原表写入动作。
- [x] 更新handoff，按文件清单提交并推送开发分支。

## 任务2：功能区、任务窗格与本机加载验证

文件：`wps-addin/main.js`、`wps-addin/ribbon.xml`、`wps-addin/taskpane.html`、`wps-addin/src/taskpane.js`、`wps-addin/styles.css`、`wps-addin/dev/server.cjs`、`wps-addin/dev/register.ps1`、`wps-addin/dev/host-probe.js`、`wps-addin/test/server.test.cjs`。

接口：功能区`OnAddinLoad`和`OnOpenRfqPane`；开发服务器`createServer({root, probeConfig, reportPath})`只服务白名单资源。侧栏通过任务1的`inspectWorkbook/readWorkbook`显示当前工作簿与各页读取结果。

- [ ] 写HTTP集成测试：插件资源可读；项目根目录和路径穿越均不能读取；非本地主机Host被拒绝；未启用诊断时不接收诊断；启用时要求随机令牌且限制请求大小。
- [ ] 运行测试观察失败，再实现静态服务及独立测试探针；探针报告不含用户清单数据。
- [ ] 编写功能区/侧栏、只读当前清单按钮、无WPS环境提示；未完成业务功能不放置可误点的假按钮。
- [ ] 注册开发插件前备份现有publish.xml；按官方publish模式仅新增/更新本插件节点，保留其他加载项，提供卸载入口。
- [ ] 启动本地服务及WPS，等待真实加载回报；在测试工作簿验证文字编码、两张表、工程量、保存后重开与中文路径，报告实际成功或失败项目。
- [ ] 阅读真实清单各页，确认多页读取；记录性能与尚未支持的情况，不修改原件。
- [ ] 完整测试与独立代码审查；记录验证证据、使用方法、下一步；提交并推送，核对远程SHA。

## 后续开发任务顺序

1. 清单解析、专业来源识别、用户可选多工作簿精确合并及来源追溯。
2. 可维护分类库、匹配依据、全部人工确认门槛、仅从确认结果学习及恢复。
3. 分类品牌表、品牌参考导入、供应商和可复用询价抬头。
4. 类别＋品牌询价工作表、分类＋供应商命名、重名预览与一键拆分，真实样本验收及离线安装包。

后续各任务开始前补齐对应实施细节，不把本接入计划宣称为一期全部完成。
